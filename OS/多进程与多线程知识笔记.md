# 多进程与多线程知识笔记

> 核心思想：
>
> **进程负责资源隔离，线程负责执行调度。**
>
> **CPU 真正调度的是线程，而不是进程。**
>
> **CPU 密集型任务关注计算能力 → 多进程/多线程并行利用多核。**
>
> **IO 密集型任务关注等待时间 → 多线程利用等待间隙提高并发。**
>
> **Python 多进程适合 CPU 密集型主要是因为 GIL，而不是线程本身不能利用多核。**

> [!NOTE]
>
> **知识精炼：**
>
> 线程是操作系统实际调度执行的单位，因此没有 GIL 限制的语言中，多线程可以实现真正的多核并行。多线程共享进程资源，通信方便、创建和切换成本低，但需要处理数据竞争。多进程提供独立地址空间和资源隔离，稳定性更高，但通信成本和创建成本更大。实际工程中通常优先使用多线程提高并发效率，只有在需要隔离、独立运行环境或避免共享状态时才选择多进程。

------

# 一、为什么需要多进程和多线程？

现代计算机同时运行大量任务：

例如：

- 浏览器播放视频
- 音乐播放器播放声音
- IDE 编译代码
- 后台同步文件
- 游戏运行逻辑

如果所有任务都只能一个一个执行：

```
任务A
↓
任务B
↓
任务C
```

CPU 利用率会很低。

因此操作系统引入了：

- **进程（Process）**
- **线程（Thread）**

让多个任务能够：

- 并发执行
- 并行执行
- 提高 CPU 利用率

> [!TIP]
>
> 用一句话总结就是，**多线程和多进程都是为了充分利用现代 CPU 的多核能力，榨干 CPU 的性能**。

------

# 二、什么是进程？

## 1. 进程的定义

进程：

> **正在运行的程序，是操作系统进行资源分配和管理的基本单位。**

程序本身是静态的：

例如：

```
main.exe
python.py
chrome.exe
```

它只是磁盘上的文件。

运行之后：

```
程序文件
    ↓
加载到内存
    ↓
形成进程
```

例如：

打开 Chrome：

```
chrome.exe 文件

        ↓

Chrome进程
```

------

# 2. 操作系统中的进程是什么样？

一个进程拥有自己的：

## （1）虚拟地址空间

例如：

```
进程A:

0x0000
 |
 |--代码区
 |
 |--数据区
 |
 |--堆
 |
 |--栈
 |
0xffff
```

另一个进程：

```
进程B:

0x0000
 |
 |--代码区
 |
 |--数据区
 |
 |--堆
 |
 |--栈
 |
0xffff
```

虽然地址一样：

```
0x1000
```

但实际上属于不同内存。

------

## （2）系统资源

进程拥有：

- 内存空间
- 文件描述符
- 网络连接
- 权限
- 系统句柄

例如：

进程 A 打开文件：

```
file.txt
```

进程 B 默认看不到。

------

# 3. 进程之间为什么隔离？

因为每个进程拥有**独立地址空间**。

例如：

进程 A：

```c
int a = 100;
```

进程 B：

```c
int a;
```

两个变量：

```
A中的a

↓

内存区域1


B中的a

↓

内存区域2
```

互不影响。

------

所以：

一个程序崩溃：

```
进程A崩溃
```

不会导致：

```
进程B崩溃
```

这就是：

> 进程隔离性

------

# 三、什么是线程？

## 1. 线程的定义

线程：

> **线程是 CPU 调度和执行的基本单位，是进程中的执行流。**

一个进程至少有一个线程：

```
进程
 └── 主线程
```

例如：

普通程序：

```
浏览器进程
    |
    |
    主线程
```

------

但是一个进程可以拥有多个线程：

```
Chrome进程
├── UI线程
├── 网络线程
├── 渲染线程
└── GPU线程
```

------

# 2. 线程和进程的关系

操作系统通过线程调度 CPU 核心；进程负责提供资源隔离和资源容器。一个进程可以包含多个线程，而这些线程可以同时运行在多个 CPU 核心上。Python 的多线程不能利用多核主要是因为 GIL，而不是线程本身不能调度多核。

可以理解为：

```
进程 = 房子
线程 = 房子里的人
```

房子提供：

- 空间
- 资源

人负责：

- 干活
- 执行任务

------

一个进程：

```
进程A

共享资源:

├──代码
├──堆
├──全局变量
├──文件


线程:

├──线程1
├──线程2
├──线程3
```

------

# 3. 线程有什么独立内容？

虽然线程共享资源，但是每个线程拥有：

- 程序计数器
- 寄存器
- 栈

例如：

```
线程1:
自己的函数调用栈

线程2:
自己的函数调用栈
```

否则多个线程无法独立执行。

------

# 四、操作系统到底调度什么？

这是最容易混淆的地方。

很多人认为：

```
CPU核心
    ↓
进程
```

实际上：

```
CPU核心
    ↓
操作系统调度器
    ↓
线程
    ↓
属于某个进程
```

------

例如：

8核心CPU：

```
CPU1
CPU2
CPU3
CPU4
...
CPU8
```

一个进程：

```
程序A

线程1
线程2
线程3
线程4
```

可以：

```
线程1 → CPU1

线程2 → CPU2

线程3 → CPU3

线程4 → CPU4
```

所以：

> 一个进程完全可以使用多个 CPU 核心。

------

# 五、多线程为什么可以利用多核？

## 没有语言限制时

例如：

- C++
- Rust
- Java
- Go

**线程直接映射到操作系统线程**。

例如：

4核心CPU：

```
线程1 → 核心1

线程2 → 核心2

线程3 → 核心3

线程4 → 核心4
```

真正并行：

```
同时计算
```

------

# 六、为什么 Python 多线程不能充分利用多核？

原因：

## GIL（Global Interpreter Lock）

Python CPython解释器存在：

> 全局解释器锁

它规定，同一时间：

```
只能一个线程执行Python代码
```

例如：

两个线程：

```
线程1:
计算

线程2:
计算
```

理论：

```
CPU1 ←线程1

CPU2 ←线程2
```

但是 GIL：

```
线程1获得GIL

计算

释放GIL


线程2获得GIL

计算
```

变成：

```
线程1
  ↓
线程2
  ↓
线程1
  ↓
线程2
```

属于“并发”，不是“并行”。

------

# 七、多进程为什么适合 CPU 密集型任务？

## 1. 什么是 CPU 密集型？

特点：

大量计算。

例如：

- 视频编码
- 图片处理
- AI训练
- 加密计算
- 数学计算

CPU：

```
████████████ 100%
```

IO：

```
很少等待
```

------

## 2. 单进程问题

例如：

4核心CPU：

```
任务:

计算A
```

单线程：

```
CPU1 ███████

CPU2 空闲

CPU3 空闲

CPU4 空闲
```

浪费核心。

------

## 3. 多进程解决

创建：

```
进程1

进程2

进程3

进程4
```

操作系统：

```
CPU1 ←进程1

CPU2 ←进程2

CPU3 ←进程3

CPU4 ←进程4
```

多个计算任务同时执行。

------

## 4. Python为什么尤其推荐多进程？

因为：

```
进程1

自己的Python解释器

自己的GIL


进程2

自己的Python解释器

自己的GIL
```

每个进程：

**都有独立GIL**。

因此：

```
CPU1 ← Python进程1

CPU2 ← Python进程2
```

实现真正并行。

------

# 八、多线程为什么适合 IO 密集型任务？

## 1. 什么是 IO 密集型？

特点：

大量时间等待。

例如：

- 网络请求
- 文件读写
- 数据库查询

例如：

下载文件：

```
发送请求
↓
等待服务器
↓
接收数据
```

等待期间：

CPU几乎没工作。

------

# 2. 单线程的问题

例如：

下载：

```
下载1

等待

完成


下载2

等待

完成
```

大量时间浪费。

------

# 3. 多线程解决

多个线程：

```
线程1 下载

等待


线程2 下载

等待


线程3 下载

等待
```

当一个线程等待：

CPU执行另一个线程。

------

所以：

IO任务：

```
等待时间多

线程切换成本低

收益巨大
```

------

# 九、多线程 vs 多进程核心区别

|          | 多线程           | 多进程       |
| -------- | ---------------- | ------------ |
| 调度单位 | 线程             | 线程         |
| 资源     | 共享进程资源     | 独立资源     |
| 内存     | 共享             | 隔离         |
| 通信     | 简单             | 复杂         |
| 创建成本 | 低               | 高           |
| 切换成本 | 低               | 高           |
| 稳定性   | 较低             | 较高         |
| 数据共享 | 容易             | 需要IPC      |
| 崩溃影响 | 可能影响整个进程 | 通常互不影响 |

------

# 十、工程实践中如何选择？

## 情况1：CPU密集型任务

例如：

```
大量计算
```

选择：

### C++ / Rust / Java：

优先：

```
多线程
```

因为：

- 开销低
- 可以利用多核

------

### Python：

选择：

```
多进程
```

因为：

- 绕过GIL
- 利用多核心

------

# 情况2：IO密集型任务

例如：

```
大量网络请求
```

选择：

```
多线程

或者

异步IO
```

原因：

等待时切换任务。

------

# 情况3：需要隔离

例如：

浏览器：

```
Tab1

Tab2

Tab3
```

选择：

```
多进程
```

原因：

一个崩溃不会影响其他。

------

# 情况4：共享大量数据

选择：

```
多线程
```

原因：

共享内存方便。

------

# 十一、实际工程选择口诀

记住：

```
需要共享数据
        ↓
      多线程


需要隔离
        ↓
      多进程


计算很多
        ↓
      多核并行


等待很多
        ↓
      提高并发
```

------

# 十二、最终理解模型

完整模型：

```
                 操作系统

                    |
              调度线程执行

                    |
                 线程
                    |
                 属于
                    |
                 进程

                    |
          提供资源和隔离环境
```

------

## 最重要的几个结论

### 1.

> 进程不是CPU执行单位，线程才是CPU调度单位。

### 2.

> 一个进程可以拥有多个线程，也可以同时运行在多个CPU核心上。

### 3.

> 多线程能否利用多核，取决于语言运行环境是否限制线程并行。

### 4.

> Python多线程不适合CPU密集型，是因为GIL，而不是线程机制的问题。

### 5.

> 多进程适合CPU密集型，是因为可以让多个独立执行环境同时占用多个核心。

### 6.

> 多线程适合IO密集型，是因为可以利用等待时间，让CPU执行其他任务。

### 7.

> 工程选择不是简单的“CPU用进程，IO用线程”，而是综合考虑：
>
> - 是否需要并行计算
> - 是否需要共享数据
> - 是否需要隔离
> - 通信成本
> - 稳定性要求

------

这套模型基本覆盖了操作系统、Python并发编程以及工程实践中关于多线程/多进程选择的核心知识。
