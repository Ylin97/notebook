# 一、完整系统架构（Serving 视角）

一个工业级 LLM 推理系统（如 vLLM / TGI）可以抽象为：

```text
                ┌──────────────┐
                │   Client     │
                └──────┬───────┘
                       ↓
                ┌──────────────┐
                │ API Server   │
                └──────┬───────┘
                       ↓
                ┌──────────────┐
                │ Scheduler    │  ← 核心（调度）
                └──────┬───────┘
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
   Prefill队列     Decode队列     KV Cache管理
        ↓              ↓              ↓
                ┌──────────────┐
                │ GPU Workers  │
                └──────────────┘
```

---

# 二、调度核心：Continuous Batching

---

## 1️⃣ 传统 batching（低效）

```text
batch1: [req1, req2, req3]
→ 一起 prefill → 一起 decode → 完成
```

问题：

- 新请求必须等待
    
- TTFT 很差
    

---

## 2️⃣ Continuous Batching（现代方案）

```text
t0: reqA prefill
t1: reqA decode1 + reqB prefill
t2: reqA decode2 + reqB decode1 + reqC prefill
```

👉 本质：

```text
Prefill 和 Decode 混合调度
```

---

## 3️⃣ 带来的提升

|指标|改善|
|---|---|
|TTFT|↓（新请求无需等待 batch）|
|吞吐|↑|
|GPU 利用率|↑|

---

# 三、为什么 Decode 是性能瓶颈？

---

## 1️⃣ Prefill vs Decode 本质区别

|阶段|瓶颈|
|---|---|
|Prefill|计算（compute-bound）|
|Decode|内存（memory-bound）|

---

## 2️⃣ Decode 慢的根本原因

每一步都要：

```text
读取 KV Cache（巨大）
→ 做 attention
→ 写回 KV Cache
```

👉 关键问题：

```text
显存带宽 < 计算能力
```

---

## 3️⃣ 一句话总结

```text
Decode = “搬数据” > “算数据”
```

---

# 四、FlashAttention vs KV Cache（高频面试题）

---

## 1️⃣ FlashAttention 是什么？

👉 一种优化 attention 的 GPU kernel

核心思想：

```text
不把完整 attention matrix 写入显存
而是在 SRAM 中分块计算
```

---

## 2️⃣ 常见误区

❌ 错误：

```text
FlashAttention 可以替代 KV Cache
```

✅ 正确：

```text
FlashAttention ≠ KV Cache
```

---

## 3️⃣ 两者关系

|技术|作用|
|---|---|
|KV Cache|避免重复计算历史 token|
|FlashAttention|优化 attention 计算过程|

👉 **可以同时使用（实际就是这样）**

---

# 五、Speculative Decoding（推理加速）

---

## 1️⃣ 核心思想

用“小模型”预测多个 token：

```text
Draft Model → 生成 5 个 token
Target Model → 一次验证
```

---

## 2️⃣ 效果

```text
减少 decode 次数 → TPOT ↓↓↓
```

---

## 3️⃣ 本质优化

```text
减少 sequential dependency
```

---

# 六、KV Cache 深度优化（进阶）

---

## 1️⃣ Multi-Query Attention（MQA）

传统：

```text
每个 head → 一套 K/V
```

MQA：

```text
多个 head → 共享 K/V
```

👉 效果：

```text
KV Cache ↓（大幅降低）
```

---

## 2️⃣ Grouped Query Attention（GQA）

折中方案：

```text
多个 head 分组共享 KV
```

---

## 3️⃣ KV Cache 压缩

|方法|效果|
|---|---|
|FP16 → FP8|显存 ↓|
|INT8 KV|显存 ↓↓|
|低秩近似|前沿研究|

# 八、系统瓶颈总结（非常重要）

---

## 1️⃣ 三大瓶颈

```text
1. Prefill → 算力
2. Decode → 显存带宽
3. KV Cache → 显存容量
```

---

## 2️⃣ 对应优化策略

|瓶颈|优化|
|---|---|
|算力|batching / 并行|
|带宽|kernel 优化|
|显存|KV 压缩 / paging|

# 十、面试“系统设计题”回答模板（重点）

---

## 🎯 问题：如何设计一个高性能 LLM 推理系统？

你可以这样答：

---

> 一个高性能 LLM 推理系统核心在于三个方面：调度、KV Cache 管理和并行策略。
> 
> 首先，在调度层采用 continuous batching，将 prefill 和 decode 混合执行，从而在保证低 TTFT 的同时提升整体吞吐。
> 
> 其次，在 KV Cache 管理上，通过分页机制（如 vLLM 的 PagedAttention）解决显存碎片问题，并结合 KV cache 压缩或 MQA 来降低显存占用。
> 
> 最后，在推理加速方面，可以结合 FlashAttention 优化 attention kernel，并通过 speculative decoding 减少 decode 步数，从而降低 TPOT。
> 
> 整体目标是在 TTFT、TPOT 和吞吐之间取得平衡。
